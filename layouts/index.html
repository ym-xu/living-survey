Method

Every morning (06:00 UTC) a GitHub Action asks the arXiv API for the last {{ $d.weeks }} weeks of papers in {{ delimit ($ax.categories | default slice) ", " " and " }} that match {{ len ($ax.queries | default slice) }} search terms. Only first releases count: a new version or cross-listing of an older paper is skipped.

A paper has to be about the topic: a topic rule is scored (title three times, abstract once) and must reach a threshold, and a list of negative patterns drops the usual false friends. Each of the {{ len $d.subfields }} subfields is a keyword rule scored the same way; a paper gets every subfield it clearly matches, and the strongest one is its main subject.{{ with $d.applications }} Papers that apply existing techniques to a domain task are kept in the list as “applications” but left out of every figure.{{ end }} Each subfield shows representative papers: hand-picked ones (“picked”) and its own main-subject papers from the last eight weeks ranked by venue acceptance, citations and public code (“recent”).

Semantic Scholar adds author IDs (so namesakes stay apart), citation counts and venues. Every rule is in map.toml; hand corrections, picks and the editor’s notes are in notes.toml.{{ with $cd }} Figure 4 comes from a card per paper: a language model ({{ delimit .models ", " }}) reads the title and abstract and picks the paper’s tasks and the methods it proposes or merely uses from fixed lists, quoting the abstract as evidence for every tag. A tag is kept only if its quote is found word for word in the abstract. Cards come only from public abstracts, so they share the abstract’s blind spots.{{ end }} It remains a rough instrument — a map of where attention goes, not a curated reading list.1
